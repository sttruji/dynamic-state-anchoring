## Experiments already run (from `docs/FINDINGS.md`)

K=16 pilot, K=8 standard-versus-FLT ablation, and a 512-question FLT data-scale run, all on one seed.
FLT improved gradient conditioning and tiny-set fitting. No run showed a validation benefit from learned
writes. The learned controller collapsed to almost never writing (8 writes in 4,000 decisions). A
loop-position-only baseline beats the controller's event AUC (0.78 vs 0.51). On today's leaderboard the
four data-scale checkpoints score 2–4/64 on dev64; the SFT checkpoint they started from scores 25/64.

## Findings

1. **The explicit CoT format changed during DSA training.** LOTUS trained the pinned CoT checkpoint on
   one step per line (`question\n<<a>>\n<<b>>\n### N`; `scripts/dataset.py`). DSA's explicit route
   joins steps with spaces (`question\n<<a>> <<b>>\n### N`; `steps_join="space"`, chosen to preserve
   the raw source text). On dev64 the original checkpoint writes newline-separated steps in 63/64
   outputs and gets 25 correct. After DSA training the four backbones write space-joined steps in
   22–42/64 outputs and get 13–17 correct. This correlates with the explicit-capability loss in
   FINDINGS; it is not shown to cause it. The `<SA>` teacher targets are also hidden states computed on
   the unfamiliar format. Cheap test: retokenize the explicit route with newline-joined steps (the
   source text is unchanged; only the join character differs) and repeat the explicit-retention check.
   The loss also holds on the 500 validation questions: the trained explicit routes score 30.6%,
   30.4% and 28.2% (static, every-loop, periodic; the learned run was interrupted), against 42.4%
   for the original checkpoint (`--model dsa --arg route=explicit`, which reproduces all 256
   FINDINGS explicit outputs). `prepare_dsa_pilot.py --steps-join newline` now builds the newline
   variant. Default `space` is unchanged. It selects the same rows in the same order with the same
   events; loop labels move in 29/512 records because the newline tokens shift positions.
   `notebooks/DSA_Format_Test_Colab.ipynb` retrains the learned arm that way on a T4, matched to the
   original run. A local MPS attempt stopped at 33/1,024 updates under memory pressure (17.7 s/update).
2. **No LOTUS GPT-2 checkpoint is public.** The `yingfanbot` hub account publishes only Llama-3B LOTUS
   models. `gsm-lotus-gpt2`, named in the CoT model card, returns 401. Getting the baseline needs the
   authors' weights or a CUDA training run of `scripts/run.py args/gsm8k_lotus_gpt2.yaml`. The
   recipe is about 4.7e18 FLOP: measured at 0.3–0.4 samples/s at stage 6 on the M1 (most of a year),
   estimated at 26–43 A100-hours with TF32. Costs and the single-GPU changes are in `BENCHMARK.md`.
3. **NL rationales receive no tags.** The annotator finds `<<a=b>>` spans and whole-line equations.
   GSM8K-Aug-NL writes arithmetic inline (`... is 100 * 50 / 100 = 50 chocolates`), so all 384,618 rows
   get zero events and DSA would get no anchor or gate supervision from that corpus. An inline-equation
   rule would need its own verified policy, as the handoff requires for any line-step dataset.
4. **Labels have a strong position prior.** The 19 October audit (uncommitted) shows timing labels are
   predictable from loop index alone. A gate that matches the labels may be learning a clock.
5. **The current scorer gives incidental credit.** The LOTUS extractor falls back to the last number.
   The leaderboard keeps it for comparability and adds a strict column.
